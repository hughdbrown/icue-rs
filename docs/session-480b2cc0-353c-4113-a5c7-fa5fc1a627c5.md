13: ## 1. Problem
14: 
15: The CORSAIR XENEON EDGE is a 14.5" 2560×720 touchscreen. On Windows, iCUE turns it into a widget
16: dashboard. On macOS it is only a plain monitor:
17: 
18: - iCUE for Mac has no Edge entry in its device catalog (`devices.json`).
19: - The HTML-widget runtime is not shipped in the Mac build. iCUE's log on this Mac lists
20:   `DisplayScreenManager.manager.dashlcd`, `WidgetPluginProviderController` and 11 more interfaces as
21:   "No implementation found".
22: 
23: EdgeHost is a macOS app that:
24: 
25: 1. drives the Edge as a dedicated dashboard surface,
26: 2. **runs unmodified iCUE HTML widgets** (`.icuewidget` packages, manifest + `index.html`) by
27:    reproducing the *public* iCUE widget contract (Widget API 1.9.0), and
28: 3. provides an **add-in controller**: a plugin system that implements the `window.plugins.*` data
29:    providers with macOS back ends, and accepts new third-party providers.
30: 
31: ### Goals
32: 
33: - G1. Widgets built with Corsair's `icuewidget` CLI install and run without edits, whenever their
34:   plugins have a macOS back end.
35: - G2. Edge layout matches iCUE: S/M/L/XL slots, landscape and portrait, multiple pages.
36: - G3. Touch input on the Edge works, including when macOS maps the digitizer to the wrong display.
37: - G4. Per-widget settings UI is generated from the widget's `x-icue-property` meta tags.
38: - G5. The permission model matches iCUE's (`file`, `folder`, `url`, …) and is actually enforced.
39: - G6. Add-in providers are isolated, versioned and negotiated against `required_plugins`.
40: 
41: ### Non-goals (v1)
42: 
43: - Controlling Corsair RGB, fans or AIOs (that is iCUE's device side; use iCUE for Mac or liquidctl).
44: - Corsair Marketplace or account integration.
45: - iCUE's native QML "screens" (pump and keyboard LCD content); only HTML widgets are in scope.
46: - Pixel-identical Chromium rendering (see §6.2 on the engine).
47: - Shipping, or depending on, any Corsair binary, built-in widget or `common/` bundle.
48: 
49: ### Naming and legal
50: 
51: - Product name **EdgeHost** (working title). Don't use "iCUE" or "CORSAIR" in the product name or icon;
52:   they are trademarks. Compatibility can be stated factually ("runs iCUE widgets").
53: - Implement from the public spec plus black-box behaviour. The reverse-engineering findings are used
54:   only to confirm architecture (interoperability). Corsair's runner repos are MIT, so code may be reused
55:   with attribution.

152: ## 4. Widget package and manifest handling (`icuew-manifest`, `icuew-package`)
153: 
154: ### 4.1 Import
155: 
156: 1. Accept `.icuewidget` (an uncompressed ZIP), `.zip` or a folder. Reject entries that escape the root
157:    (`..`, absolute paths, symlinks), and enforce size limits (default 64 MB total, 10k entries).
158: 2. Validate with the **same rules as `icuewidget-cli` 0.4.48** (see the API reference §22): required
159:    files, field regexes, the `supported_devices` set, `interactive` typing, existing `preview_icon` and
160:    `modules[]`, self-closed void elements in `<head>`, known `data-type` values, and a JSON-valid
161:    `x-icue-groups`. Report errors and warnings using the CLI's wording, so widget authors see familiar
162:    messages.
163: 3. Extra EdgeHost checks:
164:    - `supported_devices` must include `dashboard_lcd`. Otherwise warn "not designed for XENEON EDGE"
165:      and allow a forced install.
166:    - Every `required_plugins` entry is checked against the add-in registry (§7.3). Unsupported plugins
167:      are shown as *Unsupported on macOS: <name>*. The user may still install; the plugin object is then
168:      present but never initializes.
169:    - Flag Chromium-only APIs with a static scan of the JS: `queryLocalFonts`, `navigator.hid`,
170:      `navigator.serial`, `navigator.usb`, `showOpenFilePicker`, `getDisplayMedia` in a non-main frame,
171:      `CSS.registerProperty`, and others as found. These are warnings, not errors.
172:    - `os` lists only `windows`: ignore it (advisory).
173: 4. Store the package at `~/Library/Application Support/EdgeHost/widgets/<id>/<version>/`, keeping old
174:    versions until no instance references them. The install record holds the manifest, a content hash,
175:    the source and the time.
176: 
177: ### 4.2 Parsed model
178: 
179: ```rust
180: pub struct WidgetDef {
181:     pub manifest: Manifest,               // all manifest keys, unknown keys preserved
182:     pub title: Expr,                      // <title> text, e.g. tr('Name') or 'Name'
183:     pub icon: RelPath,
184:     pub group: Option<Expr>,              // x-icue-widget-group
185:     pub preview: Option<RelPath>,         // x-icue-widget-preview (128×56)
186:     pub properties: Vec<PropertyDef>,     // x-icue-property, in document order
187:     pub groups: Vec<PropertyGroup>,       // x-icue-groups
188:     pub translations: Translations,       // translation.json (en required as fallback)
189: }
190: 
191: pub struct PropertyDef {
192:     pub name: Ident,                      // `content`, also the JS global name
193:     pub label: Expr,                      // data-label
194:     pub kind: ControlKind,                // data-type (11 kinds)
195:     pub attrs: BTreeMap<String, Expr>,    // data-default, data-min, data-values, data-filters, …
196: }
197: 
198: pub enum ControlKind { Slider, Switch, Textfield, Color, Combobox, SearchCombobox, TabButtons,
199:                        MediaSelector, SensorsCombobox, SensorsFactory, StreamDeckVirtualDevice }
200: ```
201: 
202: `Expr` is the raw JavaScript expression text. Expressions are **evaluated in a webview, never in Rust**
203: (§6.4).
204: 
205: ### 4.3 Parsing `<head>`
206: 
207: iCUE parses `<head>` as XML (a vendor note says void elements must self-close). Use `html5ever` (via
208: `scraper`) for leniency, plus a separate **strict-XML check** that reproduces iCUE's import failure
209: ("Missing Title Element") as a warning. That way EdgeHost doesn't reject widgets iCUE accepts, and
210: authors are told about widgets iCUE would reject.

214: ## 5. The Edge surface (`edge-display`, `edge-layout`)
215: 
216: ### 5.1 Finding the Edge
217: 
218: - Enumerate displays with `CGGetOnlineDisplayList`. Match on EDID vendor and product from
219:   `CGDisplayVendorNumber` / `CGDisplayModelNumber` (record the Edge's values in M0) **or** on the
220:   native mode 2560×720 or 720×2560. Persist the display by `CGDisplayCreateUUIDFromDisplayID` so
221:   re-plugging reattaches.
222: - Hot-plug: use `CGDisplayRegisterReconfigurationCallback`. On removal, hide the surface and suspend
223:   webviews (`isInspectable` off, timers throttled). On return, restore.
224: - Orientation comes from `CGDisplayRotation`. A rotation change switches the layout to the portrait
225:   page set.
226: 
227: ### 5.2 Surface window
228: 
229: - A borderless `NSWindow` exactly covering `CGDisplayBounds(edge)`. `collectionBehavior` is
230:   `canJoinAllSpaces | stationary | ignoresCycle | fullScreenAuxiliary`, and the level is `.normal`
231:   (configurable to `.floating`).
232: - Pin the window to the Edge display so Mission Control and Stage Manager don't move it. Hide the
233:   window from ⌘-Tab (`NSApp.setActivationPolicy(.accessory)`).
234: - Optional keep-awake: an `IOPMAssertionCreateWithName(kIOPMAssertionTypePreventUserIdleDisplaySleep)`
235:   while the dashboard is active, with schedule-based dimming.
236: - **Release mode** (iCUE: "is now functioning as a regular monitor"): a menu toggle closes the surface
237:   and leaves the Edge as a normal monitor.
238: - Background: solid colour, image or video (a `<video>` in a dedicated background webview at z-index 0).
239: 
240: ### 5.3 Grid and slots
241: 
242: Derived from the published slot sizes. Each derivation is exact; confirm against a real Edge in M0.
243: 
244: | Orientation | Panel | Cells | Cell | Gutter | Outer margin |
245: |---|---|---|---|---|---|
246: | Landscape | 2560×720 | 3 cols × 2 rows | 840×344 | 8 | 12 |
247: | Portrait | 720×2560 | 1 col × 6 rows | 696×416 | 8 | 12 |
248: 
249: | Slot | Landscape (cols×rows → px) | Portrait (rows → px) |
250: |---|---|---|
251: | S | 1×1 → 840×344 | 1 → 696×416 |
252: | M | 1×2 → 840×696 | 2 → 696×840 |
253: | L | 2×2 → 1688×696 | 4 → 696×1688 |
254: | XL | 3×2 → 2536×696 | 6 → 696×2536 |

260: - a `Page { orientation, placements: Vec<Placement { instance, slot, origin_cell }> }` collision checker,

270: ## 6. Widget runtime (`widget-runtime`, `shim/`)
271: 
272: ### 6.1 One instance, one webview
273: 
274: | Aspect | Implementation |
275: |---|---|
276: | View | A child WKWebView in the surface window at the slot rectangle, with a transparent background (`drawsBackground = false`) |
277: | Origin | A custom scheme `icuew://<instance-uuid>/…` served by a `WKURLSchemeHandler` from the widget's version directory. A unique host per instance gives a unique origin. |
278: | Storage | `WKWebsiteDataStore(forIdentifier: instance-uuid)` (macOS 14+) gives per-instance `localStorage` and IndexedDB, mirroring iCUE's per-widget browser storage (F5). Deleting the instance deletes the store. |
279: | Process isolation | A WebContent process per webview. Watch `webViewWebContentProcessDidTerminate` and auto-reload with backoff (max 3 per 5 min), then show a "widget crashed" tile. |
280: | Frame rate | `iCUE.fpsLimit` (default 30) is advisory. Throttle hidden pages with `setAllMediaPlaybackSuspended` and by pausing rAF (removing the webview from the window while its page isn't visible). |
281: | Inspector | `isInspectable = true` in developer mode, so Safari Web Inspector can attach. |
282: | Input | `interactive: false` sets `pointer-events: none` on `<html>` via an injected stylesheet, and taps go to page-swipe handling. `interactive: true` delivers touches to the page. |
283: 
284: ### 6.2 Engine compatibility (WebKit vs Chromium 130)
285: 
286: Widgets are tested by their authors on Chromium. Known gaps on WebKit: `queryLocalFonts`, WebHID,
287: WebSerial, WebUSB, some `getDisplayMedia` cases, the File System Access API, and some CSS features.
288: Strategy:
289: 1. Static scan at import (§4.1) produces warnings.
290: 2. The compatibility corpus (§11.3) produces a pass/fail matrix per widget.
291: 3. If a significant share of real widgets fails, add the CEF engine behind `RenderEngine`, selectable
292:    per widget (`engine = "chromium"` in the instance record). That is deliberately deferred.
293: 
294: ### 6.3 Injected globals (document start, main frame only)
295: 
296: The Rust side renders `icue-shim.js` with a JSON payload and installs it as a
297: `WKUserScript(injectionTime: .atDocumentStart, forMainFrameOnly: true)`. Order of operations inside
298: the shim:
299: 
300: 1. `window.iCUE = { iCUELanguage, fpsLimit, isPreview, widgetId, defaultTemperatureUnit() }`
301:    (`widgetId` is used by the Stream Deck example but isn't on the global-object page; provide it anyway).
302: 2. `window.device = { deviceId }`: a stable UUID **without braces** for the Edge (derived from the
303:    display UUID).
304: 3. `window.uniqueId = "<instance-uuid>"`.
305: 4. **Property globals.** For each `PropertyDef`, `window[name] = <resolved value>`, taken from the
306:    instance's stored settings. The values are already concrete JSON (see §6.4), so they are available
307:    synchronously, before any widget script runs (F2).
308: 5. `window.tr = (key) => Promise.resolve(lookup(key))`, using the instance language and `en` as fallback.
309: 6. `window.plugins = {}`. For each *requested and supported* plugin, the shim creates its JS facade
310:    (§7.2) and sets `plugin<Module>_initialized = false`.
311: 7. **Modules:** for each `manifest.modules[]`, run `import("icuew://…/<path>")` and assign
312:    `window[<basename>] = namespace`, so `CitySearch.search` resolves in expressions.
313: 8. When the bridge reports provider readiness, set each `plugin<Module>_initialized = true` and call
314:    `plugin<Module>Events?.onInitialized?.()`.
315: 9. Set `iCUE_initialized = true`, then call `icueEvents?.onICUEInitialized?.()` and
316:    `icueEvents?.onDataUpdated?.()`.
317: 
318: Robustness rules (from vendor notes):
319: - Read `icueEvents` and `plugin<Module>Events` **from `window` at call time**, never cached. Widgets
320:   assign them later with bare assignment.
321: - Steps 8 and 9 run after `DOMContentLoaded` **and** after module imports settle, so late-loading
322:   scripts still see the events. Widgets also check `iCUE_initialized` themselves (late-load guard).
323: - Settings changed in the configurator reassign the property globals and call `onDataUpdated()`.
324:   Changes are debounced and coalesced to at most 10 per second.
325: 
326: ### 6.4 Evaluating attribute expressions
327: 
328: `data-default`, `data-values`, `data-label`, `data-min`, `data-max` and the other `data-*` attributes
329: are JavaScript expressions. They may use `tr()`, `iCUE`, plugin **Block** methods and manifest
330: modules. They are evaluated in an **evaluation context**: a hidden webview for the instance, loaded with
331: the same shim (steps 1–7) and a blank document. That context:
332: - computes initial defaults when an instance is created, and stores them as concrete values;
333: - computes dynamic `data-values` lists and `search-combobox` results while the configurator is open.
334: 
335: Runtime pages therefore never evaluate defaults. They receive concrete values only, which matches F2.
336: 
337: ### 6.5 Bridge protocol
338: 
339: - JS → native: `window.webkit.messageHandlers.edgehost.postMessage({v:1, id, plugin, method, args})`.
340: - Native → JS: `evaluateJavaScript("__edgehost.dispatch(<json>)")`, batched per frame (16 ms) per webview.
341: - Message kinds: `call` (async method with `requestId`), `signal` (plugin signal fan-out), `props`
342:   (property update), `ready` (provider readiness), `perm` (permission state change).
343: - **Synchronous "Block" methods** cannot round-trip through WKWebView. Each provider publishes a
344:   **snapshot** (for example the sensor catalogue: ids, types, kinds, names), which the shim injects at
345:   document start and refreshes with `signal` messages. `getDefaultSensorIdBlock(type, kind)` is then
346:   answered locally from the snapshot with the documented priority (type+kind, then type, then any, then "").
347: - Every message is validated against the plugin's declared method table. Unknown methods are dropped
348:   and logged. Message size is capped at 1 MB, and a call rate limit applies (500/s per instance).

352: ## 7. Add-in controller (`plugin-api` and `providers/*`)
353: 
354: ### 7.1 Provider contract
355: 
356: ```rust
357: #[async_trait]
358: pub trait Provider: Send + Sync {
359:     fn descriptor(&self) -> &ProviderDescriptor;          // module "widgetbuilder.sensorsdataprovider",
360:                                                           // name "Sensors", version 1.0, methods, signals,
361:                                                           // properties, block_methods, required permission kinds
362:     async fn start(&self, ctx: ProviderCtx) -> Result<()>;           // ctx: emit(signal), set_snapshot(), log
363:     async fn call(&self, inst: InstanceId, method: &str, args: Vec<Value>) -> Result<Value>;
364:     async fn subscribe(&self, inst: InstanceId) -> Result<()>;       // per-instance lifecycle
365:     async fn unsubscribe(&self, inst: InstanceId);
366:     async fn stop(&self);
367: }
368: ```
369: 
370: - **Version negotiation.** A manifest string `namespace:Name:X.Y` is satisfied by a provider with the
371:   same namespace and name and a version ≥ X.Y with the same major. Mismatches are reported at import.
372: - **Facade generation.** The JS facade in `window.plugins.<Module>` is generated from the descriptor:
373:   each method becomes `(…args) => bridge.call(...)`, each signal an object with `connect/disconnect`,
374:   each property a getter over the shim cache with `<prop>Changed` signals. The facade's shape matches
375:   the documented one exactly; the facade name is the module name minus its namespace, with the first
376:   letter capitalised (`Sensorsdataprovider`).
377: - **Fan-out.** One provider instance is shared by every widget instance. Signals are filtered per
378:   instance where the API is per-widget (Stream Deck `widgetId`) and broadcast otherwise.
379: - **Out-of-process add-ins (third party).** An executable declared in
380:   `~/Library/Application Support/EdgeHost/addins/<id>/addin.json` (descriptor and command). The add-in
381:   is launched on demand and speaks JSON-RPC 2.0 over stdio. It is crash-isolated and restarted with
382:   backoff. Custom namespaces such as `edgehost.homelab:Prometheus:1.0` let new widgets use new data;
383:   iCUE widgets are unaffected.

410: 
411: ### 8.1 Model
412: 
413: The model matches iCUE (F6): kinds `file`, `folder`, `url`, `microphone`, `camera`, `speaker`, `screen`,

425: 
426: | Kind | Mechanism |

439: ## 9. Touch (`edge-touch`)
440: 
441: ### 9.1 Problem
442: 
443: macOS has no touchscreen support. A USB HID digitizer either acts as an absolute pointer, often mapped
444: to the **main** display, or is ignored. iCUE's Windows setup exists to fix the same association problem
445: (F7).
446: 
447: ### 9.2 Design
448: 
449: - **Discovery:** `IOHIDManager` matching the Edge's VID/PID (from M0) and usage page `0x0D`
450:   (Digitizers), usage `0x04` (Touch Screen).
451: - **Exclusive mode:** open with `kIOHIDOptionsTypeSeizeDevice` so macOS stops moving the cursor. This
452:   needs the **Input Monitoring** permission (TCC `ListenEvent`).
453: - **Decoding:** use `IOHIDValue` callbacks per element (Contact Identifier, Tip Switch, X, Y, Contact
454:   Count, Scan Time) to assemble frames of up to 5 contacts. Avoid raw report parsing, so any
455:   report-descriptor layout works.
456: - **Transform:** an affine transform from digitizer logical space to panel pixels, fitted by
457:   least-squares over calibration points, then composed with the display rotation.
458: - **Gestures:** tap, long-press, drag, horizontal or vertical swipe (page change when it starts on a
459:   non-interactive area or uses 2 fingers), and pinch (passed to the page).
460: - **Delivery, in two modes:**
461:   1. **Direct (default).** Hit-test the slot, convert to webview coordinates, and dispatch synthetic
462:      `PointerEvent`s (`pointerType: "touch"`), `TouchEvent`s and a final `click` through the shim
463:      (`__edgehost.touch(frame)` → `document.elementFromPoint` → `dispatchEvent`). The cursor never moves.
464:      The caveat is that `event.isTrusted === false`; widgets rarely check it.
465:   2. **Cursor.** Post `CGEvent` mouse events at the mapped global point (needs Accessibility), then
466:      restore the cursor. Events are trusted. Use this for widgets that check `isTrusted` or for
467:      `<select>` and other native controls.
468: - **Calibration wizard** (mirrors iCUE's states). Step 1, "Touch to start" on the Edge: this confirms
469:   the digitizer belongs to this display. Step 2, "Turn off gestures": check that no macOS Accessibility
470:   or pointer-control setting is fighting the device. Step 3, 4-corner plus centre targets: fit and store
471:   the transform per display UUID and rotation. Step 4, "Calibrated".
472: - **Fallback with no digitizer access:** if the user declines Input Monitoring and macOS already maps
473:   touches to the Edge as clicks, use plain `NSEvent`s on the surface window. Detect this automatically
474:   by checking where the first touch-click lands.

611:     for (const [p, v] of Object.entries(d.props)) { let val = v;

613:     window.plugins[d.facade] = f;

619:       if (m.k === "signal") facades[m.plugin]?.f[m.name]?._emit(...m.args);
620:       else if (m.k === "prop") { facades[m.plugin].f[m.name] = m.value;

622:       else if (m.k === "props") { Object.assign(window, m.values); window.icueEvents?.onDataUpdated?.(); }

36: |---|---|---|---|

40: | `description` | string | Y | |

58: ### HTML meta tags
59: - Required: `<title>` (supports `tr('Name')`), `<link rel="icon">`.
60: - `<meta name="x-icue-widget-group" content="tr('Clock Face')">` groups widgets as variants in selector (identical names auto-group).
61: - `<meta name="x-icue-widget-preview" content="resources/preview.png">` - 128x56 px, PNG preferred, path relative to index.html.
62: - Controls: `<meta name="x-icue-property" content="<varName>" data-label=... data-type=... data-default=...>`; each becomes a global JS variable named by `content`.
63: - Property groups: `<script type="application/json" id="x-icue-groups">[{ "title": "tr('Settings')", "properties": ["a","b"], "info": "tr('help')" }]</script>`. `title` (req, JS expr ok), `properties` (req, string[] of `content` names), `info` (opt tooltip, JS expr ok).
64: - XENEON EDGE only: property groups containing `textColor`, `accentColor`, or `backgroundColor` auto-show a "Custom Style" toggle (second tab only); when off, the device default colour scheme is used.
65: 
66: ### Runtime injection and events
67: iCUE injects before widget scripts: one global per meta property, `iCUE` object, `iCUE_initialized` flag, `device` object, `window.plugins` namespace.
68: ```js
69: icueEvents = { onICUEInitialized: fn, onDataUpdated: fn };
70: if (iCUE_initialized) { onIcueInitialized(); onIcueDataUpdated(); } // late-load guard
71: ```
72: - `onICUEInitialized`: once, when API and data ready.
73: - `onDataUpdated`: every time any meta parameter changes.
74: - Plugin events: global `plugin{ModuleName}Events` (module name without namespace, first letter capitalised, rest lowercase as in examples), e.g. `pluginSensorsdataproviderEvents = { onInitialized: fn }`; readiness flag `pluginSensorsdataprovider_initialized`. Plugin objects at `window.plugins.Sensorsdataprovider`.

91: ## 5. Permissions
92: Source: https://docs.elgato.com/icue/widgets/references/permissions
93: 
94: Behaviour: pre-declared permissions in `manifest.json` are shown at install and approved before first start. Undeclared access triggers a runtime Allow/Deny dialog (allow persists). User may grant/revoke any permission at any time in widget settings; denial/revocation makes access fail silently (blocked at network/file-system level) so widgets must catch errors (`fetch`/`WebSocket` errors, empty file reads, check hardware API availability).
95: 
96: Declaration: `"permissions": [ { "type": "file", "path": "<Documents>/my-widget/data.txt" }, { "type": "folder", "path": "..." }, { "type": "url", "domain": "api.example.com", "port": 443 } ]`
97: 
98: | type | fields | notes |
99: |---|---|---|
100: | `file` | `path` (req) | read access to one file (fetch/native JS and File System Provider). Supports macros |
101: | `folder` | `path` (req) | read access to dir, any depth. Supports macros |
102: | `url` | `domain` (req: hostname/IP w/o protocol, or `"any"`), `port` (opt number) | http/https/ws/wss. Subdomains of declared domain included. `"any"` = all external non-localhost hosts. localhost requires `port`. `data:` and `blob:` always blocked |
103: | `microphone` | - | Web Audio API |
104: | `camera` | - | Media Capture API |
105: | `speaker` | - | audio output |
106: | `screen` | - | Screen Capture API |
107: | `clipboard_read_write` | - | system clipboard |
108: | `local_fonts_access` | - | Local Font Access API |
109: | `self_signed_certificate` | `host` (req) | allows self-signed TLS host, e.g. `{ "type":"self_signed_certificate","host":"localhost" }` |
110: | `download` | - | saved to iCUE-managed path |
111: | `application` | `application` (req string) | checked by plugin, not browser API; case-insensitive name; separate permission per app. Supported: `"Stream Deck"` -> plugin `widgetbuilder.streamdeck:StreamDeck:1.2`. Plugins must disconnect on denial and retry on approval |

113: Path macros (angle brackets `<Macro>` in permissions; FS-provider `watchPath` uses curly `{Macro}`, same set):

123: ## 7. JavaScript expressions & modules

136: ## 9. Local storage
137: Source: https://docs.elgato.com/icue/widgets/references/local-storage
138: - Standard Web Storage (`localStorage`, ~5-10 MB). Each widget instance has a unique id in global variable **`uniqueId`** (QUuid); it is the localStorage **key**, and the value is a JSON string holding that widget's persisted properties.
139: - Pattern: `JSON.parse(localStorage.getItem(uniqueId) || '{}')`, mutate, `localStorage.setItem(uniqueId, JSON.stringify(obj))`. Example listens to `window.addEventListener("storage", e => e.key === uniqueId ...)`.
140: - Intended for widget-render data, not core iCUE functionality.

181: ## 12. Plugin: Sensors Data Provider
182: Source: https://docs.elgato.com/icue/widgets/references/plugins/sensors-data-provider

230: ## 15. Plugin: Stream Deck Provider
231: Source: https://docs.elgato.com/icue/widgets/references/plugins/stream-deck
232: Module `widgetbuilder.streamdeck`, name `StreamDeck`, v`1.2`; `window.plugins.Streamdeck`. **Windows only.** Requires manifest `permissions` entry `{ "type": "application", "application": "Stream Deck" }` (per permissions page; runtime-requested if missing) and typically the `stream-deck-virtual-device` control.
233: Revision history: 1.1 added signals `virtualDeviceCreated`, `buttonIconUpdated`, `streamdeckUnreachable`, `authenticationRequired`, `authenticationRejected`, `reconnectStreamDeck`, `disconnectStreamDeck`. 1.2: `connectStreamDeck` no longer creates a virtual device on empty `deviceId` (use the control); deleting a widget no longer deletes its virtual device; added `streamdeckAuthenticated`.
234: Methods (synchronous calls over async RPC; results via signals):
235: - `connectStreamDeck(widgetId:string, deviceId:string, columns:int, rows:int)` - connects to an existing virtual device; on success emits `virtualDeviceCreated`.
236: - `reconnectStreamDeck(widgetId)` - async; reuses existing virtual device if it still exists (then `virtualDeviceCreated` NOT re-emitted, `buttonIconUpdated` re-emitted for known buttons once device opened); otherwise creates new device and re-emits `virtualDeviceCreated` with new `deviceId`. 237: - `disconnectStreamDeck(widgetId)` - closes session when last subscriber for `widgetId` disconnects (dashboard + mimic may share one).
238: - `updateVirtualDeviceSize(widgetId, columns:int, rows:int)` - resize without reconnect.
239: - `sendKeyPress(widgetId, buttonIndex:int, pressed:bool)` - `buttonIndex = row * columns + column` (row-major, 0-based, top-left=0); `pressed` true=press, false=release.
240: Property: `connectionStatus` string, one of `"Disconnected"`, `"Connecting"`, `"AuthRequested"`, `"Authenticated"`, `"DeviceOpened"`, `"AuthenticationRejected"`; notify signal `connectionStatusChanged()` (no args; read the property). Only reflects the widget passed to `connectStreamDeck`.
241: Signals (all `widgetId:string` first): `virtualDeviceCreated(widgetId, deviceId)`, `buttonIconUpdated(widgetId, buttonIndex:int, iconDataUrl:string data: URL)`, `streamdeckAuthenticated(widgetId)`, `streamdeckUnreachable(widgetId)`, `authenticationRequired(widgetId)`, `authenticationRejected(widgetId)`.
242: `widgetId` comes from `iCUE.widgetId` in the page's example (NOTE: `iCUE.widgetId` is NOT listed on the iCUE Global Object page - discrepancy; verify at runtime). `deviceId` from the `virtualDevice` control value.

152: ## 8. How iCUE recognises an Edge (`DashLCDScreenManager::isDashLCDDevice`)
153: 
154: Hopper via rea was impractical on the 52 MB arm64 `libiCUE`. The first run timed out waiting for the
155: first-run dialog. After the licence was added, the full auto-analysis ran its bridge script for more
156: than an hour and was stopped. The function is tiny, so it was disassembled directly instead
157: (`otool -tV -p <sym>`, then `llvm-objdump -d --start-address`):
158: 
159: ```asm
160: DashLCDScreenManager::isDashLCDDevice(QSharedPointer<CorsairDevice> const&):
161:   ldr  x0, [x1]
162:   bl   CorsairDevice::manifest() const
163:   mov  w1, #0x34            ; key 52
164:   bl   0x5af60              ; inlined QHash<int,…> lookup on the device manifest
165:   cmp  w0, #0x1a            ; == 26 ?
166:   cset w0, eq
167: ```
168: 
169: **Conclusion:** a device is a DashLCD (XENEON EDGE family) when **device-manifest property 52 equals
170: 26**, which is probably a device-category enum. Detection is data-driven: the manifest comes from the
171: downloaded `dev-*` package, and VID/PID is not hard-coded in `libiCUE`. The Mac catalog has no Edge
172: package, so the Edge's USB IDs must be captured from hardware (M0).
173: 
174: Lesson: for single small functions in huge binaries, use `otool` or `llvm-objdump` on the symbol. Use
175: Ghidra or Hopper through rea only when you need pseudocode for larger functions, and thin
176: (`lipo -thin arm64`) and preferably split the target first.

Split out crates only after a boundary is proven stable. The current repo already only has 4 workspace members, so the code reality is closer to this than the spec.

### B. Touch input assumptions are unverified and likely fragile

SPEC §9 assumes:

1. The Edge digitizer presents as a USB HID digitizer with usage page `0x0D`, usage `0x04`.
2. `IOHIDManagerOpen(..., kIOHIDOptionsTypeSeizeDevice)` will stop macOS from moving the cursor.
3. If the user denies **Input Monitoring**, a fallback using plain `NSEvent` clicks on the surface window will work.

These are all hardware-dependent. If macOS already treats the digitizer as an absolute mouse mapped to the main display, seizing it is the right fix, but:

- **Input Monitoring** is a high-friction TCC permission; many users will deny it.
- Synthetic `PointerEvent`/`TouchEvent` injected from JS are **not trusted** (`event.isTrusted === false`). Some widgets and native controls will misbehave.
- The “cursor mode” fallback using `CGEvent` requires **Accessibility**, which is another TCC prompt, and restoring the mouse cursor smoothly is non-trivial.

**Suggestion:** M0 hardware verification must answer whether macOS maps touch to the Edge at all. If it does, the whole touch stack can be much simpler (NSEvent-based). If it does not, make Input Monitoring required for interactive widgets and be honest in the UI.

### C. Synchronous “Block” methods cannot really be synchronous in WKWebView

SPEC §6.3 and §6.4 say Block methods like `getDefaultSensorIdBlock` are answered locally from a cached snapshot. The current shim evaluates `data-default` expressions at document start with `new Function("tr", ...)`; plugin data and module imports are not available yet, so any default that calls `plugins.Sensorsdataprovider.getDefaultSensorIdBlock(...)` will fail.

This is a real mismatch with iCUE, where QWebChannel supports synchronous native calls in the expression context.

**Suggestion:** implement the “evaluation context” hidden webview exactly as described in §6.4, but it must wait for provider snapshots to be ready before evaluating defaults. Runtime webviews should never evaluate expressions; they only receive concrete property values.

### D. The permission engine has gaps

SPEC §8 proposes `WKContentRuleList` for `url` enforcement. Content-rule lists are designed for `http`/`https` network loads and may not behave as expected for custom schemes or `blob:`/`data:` navigations. Also, `url` rules for subdomains/ports need careful testing on WebKit.

`file`/`folder` access is supposed to go through `icuew://<inst>/__fs/<macro>/<path>`. Widgets that use ordinary `<img src="file:///...">` or `fetch("file://...")` will normally be blocked by WebKit, but the spec should explicitly test this.

`local_fonts_access` and `speaker` are admitted no-ops. That is fine, but the user should be told they are not enforced.

**Suggestion:** treat permissions as a phased feature. In M1/M2 only `url`, `file`, `folder`, and `download` need real enforcement. `microphone`/`camera`/`screen` can be denied by default. `application`, `local_fonts_access`, `speaker`, `self_signed_certificate`, and `clipboard_read_write` can be stubs with warnings.

### E. The built-in provider list is too ambitious for v1

SPEC §7.2 plans full implementations of sensors, media, link, filesystem, notifications, fps, deviceaction, and streamdeck. Several are problematic on macOS:

- **Sensors:** reading CPU/GPU temps reliably requires SMC/IOReport/IOHIDEventSystem and varies by Apple Silicon generation. This is doable but fragile.
- **Media:** Now Playing via MediaRemote requires an entitlement on macOS 15.4+; the “out-of-process helper” idea is correct but adds significant work.
- **Notifications:** there is no public API for counting other apps’ notifications. Reading `usernoted` is brittle and may break with OS updates.
- **FPS:** system-wide FPS is genuinely unavailable; this should be a stub.
- **Device Action / Stream Deck:** the Edge has no dials; Stream Deck is Windows-only. These should be stubs/marked unsupported.

**Suggestion:** for v1, implement only **link**, **filesystem**, and a basic **sensors** provider (CPU/memory load, not temps). Add **media** next. Mark notifications, fps, deviceaction, and streamdeck as unsupported. Do not build the full add-in registry UI until built-in providers are stable.

### F. The CEF fallback should not be a v1 plan

SPEC §6.2 says “If a significant share of real widgets fails, add the CEF engine behind `RenderEngine`.” Shipping CEF on macOS is a massive undertaking: binary size, signing, update cadence, and licensing. It should not be in the v1 plan at all.

**Suggestion:** make WebKit the only engine. Document known incompatibilities (WebHID, WebUSB, File System Access API, etc.) and warn widget authors. Revisit a second engine only after the corpus proves it is unavoidable.

### G. Display detection and orientation need hardware truth

SPEC §5.1 proposes matching by EDID vendor/product or exact native mode. The current code in `host.rs` only matches by monitor size (`2560×720` or `720×2560`). This will fail if:

- The Edge is connected through a hub that reports a different EDID or size.
- macOS applies overscan/underscan or HiDPI scaling.
- The panel is rotated but `CGDisplayRotation` does not reflect the physical orientation.

**Suggestion:** M0 must capture `ioreg`, `hidutil list`, `system_profiler SPDisplaysDataType`, and the actual `CGDisplay` info. Also provide a manual “this is my Edge” picker in the configurator so auto-detection is not the only path.

### H. The shim currently evaluates defaults in the runtime webview

The starter `icue-shim.js` evaluates `data-default` at document start. That contradicts SPEC §6.4, and will break as soon as you support sensors-combobox defaults or manifest modules.

**Suggestion:** keep the runtime shim simple (globals, property values from Rust, plugins, events). Move all expression evaluation to the evaluation-context webview.

### I. `docs/design/prompt.md` conflicts with the product spec

`docs/design/prompt.md` says:

> Make a replica of Corsair application `ICue`…

while `docs/SPEC.md` §1 correctly warns not to use “iCUE” or “CORSAIR” in the product name because they are trademarks and to call the project **EdgeHost**.

**Suggestion:** delete or rewrite `docs/design/prompt.md` to describe EdgeHost and reference the same sources, so the two documents do not contradict each other.
